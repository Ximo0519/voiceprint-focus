# CPU 绑核（VF_CPU_AFFINITY）

默认 **关**。不设这个变量时，服务行为和以前完全一致：进程不绑核，由 Windows 调度器
在全部逻辑核之间分配。

启动时会自检并把结果写进 `/api/health` 的 `cpu_affinity` 字段：

- `topo`：物理核数、逻辑核数、是否 SMT、是否大小核、P/E 逻辑 CPU 列表；
- `bench_ms`：大小核机器上，单块推理在「一颗 P 核」和「一颗 E 核」上的耗时（各测 2 块取快值）；
- `mode / applied / cpu / cpu_label / load_pct`：当前是否真的绑了、绑到哪颗、当时该核负载。

核号不写死：`P/E` 列表来自 `GetLogicalProcessorInformationEx` 的 EfficiencyClass，
换机器会重新排列；显式指定时用的是**列表下标**，不是系统 CPU 编号。

## 取值

| 值 | 含义 |
|---|---|
| `off`（默认）/ `none` / `0` | 不绑核 |
| `auto` / `p` | 自检后用 0.3s 采样挑一颗**当前最闲的 P 核**并绑上去 |
| `p0` / `p1` / `p2` … | 按自检出的 P 核列表下标绑定（`p0` 是列表第一颗） |
| `e` | 绑一颗 E 核（只用于对照/排查，不建议生产用） |

设置方式（PowerShell，重启生效）：

```powershell
$env:VF_CPU_AFFINITY='auto'    # 或 off / p0 / e
python server.py
```

## 适合开的机器

- 单路实时（一次只有一个 WebSocket 流）是主要形态；
- 机器上还有杀毒扫描、索引、浏览器、IDE 等常驻负载，推理线程经常被迁移或抢核；
- 大小核笔记本：希望稳定落在 P 核，避免部分块被调度到 E 核（E 核单块通常是 P 核的 4–6 倍耗时）；
- 已经确认绑上去的那颗核**当前不忙**（看 health 里的 `load_pct`，或先跑一次 `auto` 看结果）。

## 不适合开的机器

- 需要同时服务多路音频：绑单核会把所有流挤到一颗核上，吞吐显著下降；
- 容器/虚机里 cpuset 已经收窄、或逻辑 CPU 编号与物理拓扑不对应（`topo.source` 会退回 `fallback`）；
- 目标核本身被占（例如杀毒把某个核吃满 150%）：绑上去会比不绑更差，这时应换 `p1`/`p2` 或直接 `off`；
- 对尾延迟不敏感、但追求总吞吐的离线批处理。

## 结论口径

绑核只减少「迁移 + 争核」带来的抖动，不会凭空提升单核算力。如果机器整体被别的进程压住
（例如 Defender 实时扫描），绑核救不了；先排除干扰源再看绑定收益。
